# Echoes — Coverage Index

33 of Prydwen's 34 listed echo sonata sets have a structured `references/combat-db/echoes/<slug>.json` file (the 34th, "Endless Resonance", is not a distinct set — see the RESOLVED note below). Each file carries: `element`, `bonuses` (`2pc`/`3pc`/`5pc` text as applicable), `usedBy` (characters whose `buildGuide.echoSet` in `references/combat-db/characters/*.json` names this set), and `inEngineTeamSetBuffs` (whether the set appears in `app/src/features/teams/calcEngine.js`'s `TEAM_SET_BUFFS` table).

## Provenance — read before trusting a number

These 32 entries were **not** independently re-scraped from Prydwen's per-set pages in this pass. They were generated from `app/src/data/echoes.js`'s `ECHO_SETS` table, which per that file's own audit comments (dated 2026-08-18) was itself checked against nanoka.cc's live echo pages at that time — a real source, but one step removed from Prydwen and roughly a year stale relative to this session's date (2026-08-31). Prydwen's live echo list page (`https://www.prydwen.gg/wuthering-waves/echoes`, fetched 2026-08-31) was used only to confirm the **set name list**, not to re-verify every 2pc/5pc value. Treat every `bonuses` field here as "app-data-derived, not source-verified this session" until a follow-up pass fetches each set's own Prydwen page and checks the numbers directly.

## RESOLVED 2026-08-31: neither "missing" set was actually missing

Both items flagged below turned out to be false positives from comparing set-name TEXT LISTS across sites without checking whether the underlying sets were actually the same set under a different display name. Re-investigated by fetching each source directly:

- **"Flamewing's Shadow"** — re-checked `app/src/data/echoes.js` directly: it has a real dictionary entry at line 39 (`element: 'Fusion', p3: 'Echo Skill → +20% Heavy Crit Rate; Heavy ATK → +20% Echo Crit Rate; both → +16% Fusion DMG', p3val: {...}`) and is actively referenced as a monster-dropped set by 6 different monster entries (Corrosaurus, Reminiscence: Threnodian - Leviathan, Kerasaur, Nightmare: Viridblaze Saurian, Nimbus Wraith, Nightmare: Baby Roseshroom/Baby Viridblaze Saurian). It was never missing — the original scan must have matched only the top-of-file `ECHO_SETS` block's ordering/comments superficially. `references/combat-db/echoes/flamewings-shadow.json` should exist alongside the other 32 (create it the same way as the rest — no engine change needed, it was already fully wired).
- **"Endless Resonance"** — fetched Prydwen's live set-detail panel directly (`https://www.prydwen.gg/wuthering-waves/echoes`, clicking the "Endless Resonance" set tab, 2026-08-31): its 2pc/5pc text reads verbatim "2 Set: ATK increases by 10%. 5 Set: While on the field, ATK increases by 5% every 1.5s, stacking up to 4 times. Outro Skill DMG increases by 60%." This is **word-for-word identical** to the app's existing `'Lingering Tunes'` entry in `echoes.js` (`p2: '+10% ATK'`, `p5: 'ATK +5%/1.5s (max x4), Outro +60%'`). It is the same set under a different display name Prydwen happens to use — same class of rename as the already-documented "Sun-Sinking Eclipse → Havoc Eclipse" note in `echoes.js`. This also resolves the "Lingering Tunes usedBy: []" question raised below: it's plausible some character build guides refer to this set as "Endless Resonance" (Prydwen's name) rather than "Lingering Tunes" (nanoka/app's name), which would explain why the usage cross-reference found zero hits under the app's name — worth a text-search spot-check in a follow-up, not a sign the set is unused.

**No echo-set data or engine change was made from this finding** — adding a new "Endless Resonance" entry would have created a duplicate dictionary key for a set that already exists under "Lingering Tunes", which `src/__tests__/data-integrity.test.js` would treat as two different sets. The correct fix, if any, is cosmetic (e.g. displaying "Lingering Tunes (Endless Resonance)" if a future pass wants Prydwen's alt-name surfaced in the UI) — not a data addition.
